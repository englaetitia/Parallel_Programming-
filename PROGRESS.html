Step 1 — Create our virtual machines (VMs)

In progress started 20 Nov 2026
Why this step? MPI needs several computers that run the same system and the same MPI version. Laetitia's and Georges-Anthony's laptops are different (Windows, different settings). So each of us runs a small virtual machine: a "computer inside the computer" running Ubuntu Linux. All the VMs are identical, so MPI sees a clean, uniform cluster.

Who does what

Both of us do this step, each on our own laptop. Each VM gets a name: heat-laetitia and heat-georges. We also need a third machine (a lab PC, a family laptop…) because the final demo needs at least 3 VMs.

1. Install Multipass on the laptop (Windows) — from the terminal

Open PowerShell as Administrator (Start → type "PowerShell" → right-click → Run as administrator).

# a) Which Windows edition do I have? (Home or Pro decides the VM engine)
(Get-ComputerInfo).WindowsProductName

# b1) Windows PRO only: turn on Hyper-V, then restart the PC
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All

# b2) Windows HOME only: install VirtualBox (Multipass uses it as the engine)
winget install Oracle.VirtualBox

# c) Install Multipass (both editions)
winget install --id Canonical.Multipass -e --accept-source-agreements --accept-package-agreements

# d) Check it is installed
winget list multipass                                         # shows: Multipass  Canonical.Multipass  1.17.0
Test-Path "C:\Program Files\Multipass\bin\multipass.exe"     # shows: True

# e) If "multipass is not recognized": add it to PATH for this window
#    (restarting Windows fixes it permanently)
$env:Path += ";C:\Program Files\Multipass\bin"

# f) Final check
multipass version            # multipass 1.17.0+win / multipassd 1.17.0+win
multipass get local.driver   # hcs  (the new Windows engine in Multipass 1.17 — normal)

Simple words: winget is Windows' built-in app installer for the terminal. The driver is the engine that actually runs the VM; in Multipass 1.17 on Windows it is called hcs (it replaced the older hyperv driver).

2. Create the VM (in PowerShell)

multipass launch 24.04 --name heat-laetitia --cpus 2 --memory 4G --disk 15G
multipass list                     # should show heat-laetitia "Running"
multipass shell heat-laetitia      # opens a terminal INSIDE the VM

Georges-Anthony uses --name heat-georges. If your laptop has many cores and lots of RAM, you can give more (e.g. --cpus 4 --memory 8G).

3. Install the software (inside the VM)

sudo apt update
sudo apt install -y build-essential cmake git openmpi-bin libopenmpi-dev python3-numpy python3-matplotlib
mpirun --version      # write down the version: it must be the SAME on every VM
g++ --version

What these are: build-essential = the C++ compiler; cmake = build tool; openmpi = the MPI library and mpirun; numpy/matplotlib = for plots later.

4. Get our code inside the VM

cd ~
git clone https://github.com/englaetitia/Parallel_Programming-.git heat
cd heat && ls

Both VMs must keep the code at the same path (/home/ubuntu/heat), because MPI starts the program at the same place on every machine.

Workaround: download Ubuntu ourselves, verify it, launch from the file

# 1. Download with curl.exe (built into Windows). "-C -" resumes if the connection drops:
#    just run the same line again until it finishes.
curl.exe -L -C - -o "C:\Users\User\Downloads\noble.img" https://cloud-images.ubuntu.com/releases/noble/release/ubuntu-24.04-server-cloudimg-amd64.img

# 2. Get the official fingerprints and our file's fingerprint
curl.exe -L https://cloud-images.ubuntu.com/releases/noble/release/SHA256SUMS | Select-String "server-cloudimg-amd64.img"
Get-FileHash "C:\Users\User\Downloads\noble.img" -Algorithm SHA256

# 3. If the two fingerprints are identical, launch from the local file
multipass launch file:///Users/User/Downloads/noble.img --name heat-laetitia --cpus 2 --memory 4G --disk 15G   # no "C:" (see rows 13-15)

Simple words: the SHA256 fingerprint is a long code computed from every byte of a file. Change one byte and the code changes completely. Comparing ours with Ubuntu's official one proves the file is complete.

If something goes wrong

  • "launch failed" / timeout: run the launch again; the first download of Ubuntu can be slow.
  • Hyper-V not available (Windows Home): choose VirtualBox during Multipass install.
  • apt errors: run sudo apt update again, then retry the install.
  • "multipass is not recognized": run $env:Path += ";C:\Program Files\Multipass\bin" or restart Windows.
  • "Hash … does not match": the download was damaged. Clear the cache (as Administrator) or use the download-and-verify workaround above.
  • "Cannot open Multipass service": PowerShell is not running as Administrator.

Simple words

  • VM (virtual machine): a full computer simulated by software inside your laptop.
  • Multipass: a tool that creates Ubuntu VMs in one command.
  • vCPU: a processor core given to the VM. Later, we run at most this many MPI processes per VM.
